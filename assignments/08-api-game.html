Assignment 8: An API-Powered Game

Due: Tuesday, 12/1/26, before class.

Goal

Build a small game where your server talks to two things outside of it: a free public API that supplies the game (words, Pokémon, cards, or trivia questions), and a MongoDB Atlas database that saves everyone's results. A player uses buttons or a form on your page, your server does the work, and the page updates.

Every piece of this is something we've done in class: fetch to our own server, routes in Express, POST with a JSON body, calling an outside API from the server, secrets in .env, saving and reading with MongoDB, and hosting on Render. This assignment puts them together.

Useful examples: Calling the Gemini API from Our Server (server calls an outside API and sends the result to the page) and the MongoDB example from class on Friday 11/20.

Pick a Game

Pick one of these three, or make up your own game using any API you want. The three APIs below are free and need no API key. If the API you choose needs a key, that's fine: keep it secret the same way as your MongoDB connection string (see requirement 3).

1. Higher or Lower (Pokémon)

Two Pokémon appear, along with a random stat, like "Which one has more speed?" or "Which one has more HP?" Every right answer adds to your streak, and every round asks about a different random stat (if they tie, either answer counts). One wrong answer ends the game, and your streak goes on the leaderboard.

  • API: PokeAPI. https://pokeapi.co/api/v2/pokemon/ID, where ID is a number from 1 to 1025. The answer includes name, a picture in sprites.front_default, and a stats array with six stats (hp, attack, defense, special-attack, special-defense, speed). Each one looks like { base_stat: 90, stat: { name: "speed" } }. You can also use weight and height.
  • Front end: the question ("Which has more speed?"), two pictures and names, and a button under each. Show the current streak. When the game ends, ask for a name to save the score, and show the top 10.
  • Back end: a route that picks two random Pokémon and a random stat, fetches both Pokémon, finds that stat for each one (a loop over stats), and sends back what the page needs. A POST route that saves a score. A GET route for the leaderboard.

2. Card Shark

Higher or lower with a real shuffled deck. You see a card. Will the next one be higher or lower? Keep going until you're wrong.

  • API: Deck of Cards API. https://deckofcardsapi.com/api/deck/new/shuffle/?deck_count=1 shuffles a new deck and gives you its deck_id. Then https://deckofcardsapi.com/api/deck/DECK_ID/draw/?count=1 draws a card, with an image, value, and suit.
  • Front end: the current card's picture, Higher and Lower buttons, the streak, and the best runs from everyone.
  • Back end: a route that starts a game (shuffle and draw the first card), a route that draws the next card, a POST route that saves a finished game, and a GET route for the best runs.

3. Trivia

Answer multiple-choice questions. Your score goes on a leaderboard that everyone shares.

  • API: Open Trivia Database. https://opentdb.com/api.php?amount=10&type=multiple gives 10 questions, each with question, correct_answer, incorrect_answers, category, and difficulty.
  • Front end: one question at a time, with the four answers as buttons (mixed up, so the right one isn't always in the same place). Show right or wrong after each. At the end, save the score with a name and show the leaderboard.
  • Back end: a route that fetches the questions, a POST route that saves a score, and a GET route for the leaderboard.

Requirements

  1. Set up the folder
    cd into 08-api-game and run: 
    npm install express mongodb dotenv
    Add "type": "module" to package.json, like Assignment 7. Make a .gitignore with these two lines: 
    node_modules
.env
  2. Set up MongoDB Atlas
    Follow along with what we did in class on 11/20: make a free account, create a Free cluster, make a database user, and copy your connection string. Put it in .env: 
    MONGODB_URI=mongodb+srv://USERNAME:PASSWORD@cluster0.xxxxx.mongodb.net/
    In Atlas, under Network Access, allow access from anywhere (0.0.0.0/0). Otherwise Render can't connect.
  3. Your server calls the outside API
    The browser never calls the game's API directly. Your script.js only ever fetches your own routes, and your server fetches the outside API and sends back what the page needs. If your API needs a key, put it in .env (for example API_KEY=...), read it with process.env.API_KEY, and add it to Render's Environment tab too. Never put a key in your code, and never in script.js.
  4. The front end updates the page
    Buttons and/or a form that fetch from your server and update the page with what comes back. No page reloads.
  5. Save to MongoDB
    At least one POST route that receives JSON (express.json() and req.body) and saves it with insertOne. For example: a name and a score, or a new word and who added it.
  6. Read from MongoDB, with a filter or a sort
    At least one GET route that uses find with a filter (for example { category: "History" }) or a sort (for example highest score first), and sends the results to the page. The page shows them (a leaderboard, best runs, everyone's captions).
  7. Test it on your computer first
    Run node server.js and play your game at http://localhost:3000. Check your data in Atlas under Browse Collections.
  8. Host it on Render
    Same as Assignment 7, with Root Directory assignments/08-api-game. Your .env isn't pushed, so Render doesn't have it: in your service's Environment tab, add MONGODB_URI with the same connection string. Use const port = process.env.PORT || 3000; like before.
  9. README.md: your link, and trace one click
    Put your Render link at the top. Then, in your own words (a short paragraph, 4 or 5 sentences), pick one button or form in your game and explain everything that happens when someone uses it: what the front end sends, which route on your server receives it, what your server asks the outside API or MongoDB, and what comes back to the page.
  10. Code comments
    Add your own HAND-WRITTEN comments to server.js and script.js explaining what each part does.

Things That Will Trip You Up

  • Do Atlas and Render first. The hardest part of this assignment is usually not the game. It's the connection string, the Atlas Network Access setting, or Render's Environment tab. Get a server on Render that saves one document to Atlas before you build the game, right after class on 11/20.
  • Passwords with symbols. Characters like @, :, or / in your database password break the connection string. Use a password with only letters and numbers.
  • "Connected" never prints. Check that .env is in the same folder you run node server.js from, that the password in the string is right (no < > left around it), and that Network Access allows your IP.
  • Numbers that are strings. Values from inputs, query parameters, and some APIs are strings. "10" > "9" is false! Use Number(...) before you compare or save a score.
  • Card values. The Deck of Cards API gives values like "8", "KING", and "ACE". You'll need to turn those into numbers yourself.
  • Trivia limits. Open Trivia only lets you ask once every 5 seconds. Ask too fast and you get response_code: 5 and no questions, so get all your questions in one request. Questions also come with codes like &#039; for '. Putting them on the page with innerHTML shows them correctly.
  • Changes on Render. After pushing a fix, click Manual Deploy, then Deploy latest commit. If you change an environment variable, Render redeploys for you.
