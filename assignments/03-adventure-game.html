Assignment 3: Adventure Game

Due: Tuesday, 9/29/26, before class.

Goal

Build a small text-based adventure game: a world made of rooms, an inventory, and at least two different kinds of "locked" things that stand between the player and finishing the game. Everything the player sees should be generated by JavaScript from data you write (arrays and objects) and rendered onto the page the same way we've built dynamic content in class, just with more pieces working together.

This assignment intentionally restricts you to a small, specific toolbox (below). The point isn't necessarily the game itself; it's leaving this assignment able to understand everything in the toolbox. A flashier game built with tools outside the list is not what I am looking for.

Requirements

  1. A world of rooms
    One JavaScript object, keyed by room id, holding at least 4 rooms. Each room needs a name, a description, and a list of exits (an array of { label, destination } objects). Write one render function that clears a container and rebuilds it from the current room.
  2. An inventory
    An array, starting empty, that items get pushed into when picked up. Your page must display the current inventory (a list, re-rendered from the array whenever it changes) so the player can see what they're carrying. You need at least 2 different items to pick up.
  3. Usable items
    Items in the inventory list should be clickable. Clicking one "uses" it. If that item has an effect, show what happens by updating the current room's description text. Not every item needs an effect; clicking one that doesn't can just do nothing.
  4. A lock that needs an item to open
    At least one exit, room, or object that's inaccessible until the player has a specific item in their inventory. Check this with a plain for loop scanning the inventory array, not a shortcut array method (see Allowed Tools below). When the condition is met, use classList to reveal the exit or remove a "locked" indicator.
  5. A lock that needs a conversation
    At least one lock that opens not from an item, but from talking to an NPC. For example, a flag that only becomes true once the player has clicked through all of that NPC's lines.
  6. A hidden password
    Somewhere in the game (in an item's description, in something an NPC says, wherever you like) reveal a password string. Provide a plain <input type="text"> and a button (no <form>). Clicking the button compares input.value to the expected password and reports whether it's correct. Getting it right should unlock or reveal something; this can be your "ending."
  7. At least one mouseover interaction
    Somewhere on the page, hovering over something should do something useful with JavaScript. For example, hovering an inventory item could show its description in a status area. (This is separate from CSS :hover, which you should also still use for basic button feedback.)
  8. Styling
    Box model (padding, margin, border, border-radius), flexbox for layout (for example, an inventory sidebar next to the main scene), and :hover on buttons.

Allowed Tools

This assignment is graded partly on staying inside this list.

  • HTML: div, span, h1–h3, p, ul/li, button, input type="text". No <form>, no <img> (use emoji/text for items).
  • CSS: element/class/id selectors, :hover. Box model, flexbox, typography, color properties. No transition, animation, transform, or position.
  • Variables: let and const only.
  • Loops: classic for with an index only. No for...of, no .forEach.
  • Functions: the function keyword only. No arrow functions.
  • Array methods: .push() only. "Do I have this item?" is a manual for loop scan, not .includes().
  • DOM selection: document.querySelector() only (not querySelectorAll).
  • DOM creation: document.createElement(), .appendChild().
  • Content: .textContent, .value. .innerHTML only ever as = "" to clear a container before rebuilding it, never to build content.
  • Visual state: classList.add() / .remove() / .toggle() / .contains().
  • Events: addEventListener, only with "click" or "mouseover".
  • Randomness/timing: Math.random() and setTimeout() are allowed if you find a good use for them, though neither is required.

A Note on Generative AI

Do not use ChatGPT, Copilot, Claude, or any other generative AI tool to write any part of this assignment. The whole point of the restricted toolbox above is to build real fluency with these exact foundational aspects of front end programming. We'll get to fancy stuff soon enough.
