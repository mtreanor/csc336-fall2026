Assignment 5: E-commerce Store Inventory

Due: Tuesday, 10/20/26, before class.

Goal

Assignment 4 was the shopper's side of your store. This one is the shop owner's side: an "Add New Product" form that puts new products into your catalog. And this time they stick around. Your products are saved in localStorage, so refreshing the page doesn't lose them.

You're building on your own Assignment 4 code, using what we covered on 10/9: forms, preventDefault, turning form fields into an object, and saving data with JSON.stringify/JSON.parse and localStorage.

Getting Started

Copy your whole 04-ecommerce folder into a new folder named 05-inventory-tool, and do all of your work there. Don't change 04-ecommerce, it needs to stay exactly as it was when you turned it in.

Requirements

  1. An "Add New Product" form
    A <form> somewhere on the page with a field for every property your products have:
    • name: a text input
    • price: a number input (use min and step="0.01" so cents work)
    • description: a <textarea>
    • category: a <select> with your store's categories
    • image: a URL input (type="url") for a link to a picture
    Every field should be required, so the browser won't let the form submit with anything missing.
  2. Submitting builds a product
    Listen for the form's "submit" event and call event.preventDefault() so the page doesn't reload. Read each field, build a new product object with the same properties as your existing products, and push it onto your products array. Remember that .value is always a string, even on a number input: the price needs to be a real number (use Number()), or your cart total will break. Clear the form after a product is added.
  3. New products are real products
    A new product shows up in the catalog right away, and it works with everything from Assignment 4: the category filter (and sorting, if your store has it), its own "Add to Cart" button, and the checkboxes for "Add Selected." If it only half works, check that its object really matches the shape of the others.
  4. One validation rule of your own
    Pick one rule the browser can't check for you, and enforce it in your submit handler. If the rule is broken, don't add the product, and show a message on the page (not an alert) saying what's wrong. Some ideas: no two products with the same name, a description of at least 20 characters, a price under some maximum.
  5. Products saved in localStorage
    Save your products array every time it changes (JSON.stringify, then localStorage.setItem), and load it when the page starts (localStorage.getItem, then JSON.parse). The very first time someone visits, nothing has been saved yet and getItem gives back null. In that case, use your starter products from Assignment 4. Refresh the page after adding a product: it should still be there.
  6. A "Reset Store" button
    A button that clears your saved products (localStorage.removeItem) and puts the catalog back to your starter products. You'll want this while testing, and whoever grades your assignment will use it too.

Things That Will Trip You Up

  • Whoever grades this is using a different browser. localStorage lives in one browser on one computer, so the products you added won't be there for anyone else. They'll see your starter products and add their own. Make sure the starter catalog still looks like a real store.
  • Changing your product shape breaks saved data. If you rename a property (say, price to cost) after you've already saved products, the old saved ones still say price. Click Reset Store whenever you change the shape of a product.
  • Don't save checkbox state. If your Assignment 4 code marks products with something like selected: true, that gets saved too, and products come back already checked after a refresh. Clear it before saving, or set every product back to false when the page loads.
  • Seeing what's saved: open DevTools, go to the Application tab, and look under Local Storage. You can see (and delete) exactly what your page saved.

Challenges

Not required: the requirements above are a complete assignment. Challenges are how you go beyond it. One that's finished and working beats several that are half-wired.

  • Delete a product
    A delete button on each card. .filter() is a clean way to build a new array without it. Don't forget to save afterward.
  • Edit a product
    An edit button on each card that fills the form with that product's values. Saving should change the existing product, not add a new one. (A closure in your render function already knows which product the button belongs to.)
  • Save the cart too
    Right now a refresh still empties the cart. Save it in localStorage under its own key. Watch out: after a trip through JSON, cart items are copies of your products, not the same objects, so === comparisons between them stop working. Saving just each product's name in the cart, and looking the product back up when the page loads, avoids that.
  • Live preview
    Show what the new product's card will look like, updating as the user types. The "input" event fires on every keystroke.
  • Upload an image instead of a URL
    Use <input type="file"> and FileReader's readAsDataURL to turn a picture into a string you can save. Keep the images small: localStorage only holds about 5 MB.
  • Export the catalog
    A button that downloads your products as a .json file.
